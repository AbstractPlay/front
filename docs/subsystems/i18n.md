# Internationalization

The client uses **i18next** with **react-i18next** for translatable UI strings.

## Key files

| File | Role |
|------|------|
| [`src/i18n.js`](../src/i18n.js) | i18next initialization and supported language list |
| [`src/index.js`](../src/index.js) | Imports `./i18n` before render |
| [`src/components/LanguagePicker.js`](../src/components/LanguagePicker.js) | Footer language dropdown |
| `public/locales/` | Translation JSON files (loaded via HTTP backend) |
| `src/locales/en/` | Bundled English copy (synced from `public/locales/en/` at build time) |

## Configuration

From [`i18n.js`](../src/i18n.js):

- Namespace: `apfront`
- Fallback language: `en`
- Supported languages: `en`, `fr`, `de`, `it`
- Backend: `i18next-http-backend` (loads from `/locales/{{lng}}/{{ns}}.json`)
- Detector: `i18next-browser-languagedetector` with `localStorage` before `navigator`

Language resolution order:

1. Manual choice in the footer (stored in `localStorage` as `i18nextLng`)
2. Browser / system language
3. English fallback (including unsupported locales)

## English locale sync

Author English strings in `public/locales/en/apfront.json`. The bundled fallback imported by `i18n.js` lives at `src/locales/en/apfront.json` and is copied automatically by `npm run copy-locales`, which runs before `start`, `build-dev`, and `build-prod`. You do not need to run `npm run extract` for this copy step.

## Usage in components

```javascript
import { useTranslation } from "react-i18next";

function MyComponent() {
  const { t } = useTranslation();
  return <span>{t("some.key")}</span>;
}
```

`Skeleton` wraps the app in `Suspense` because `useTranslation` can suspend while loading locale files.

## Extracting strings (optional)

```bash
npm run extract
```

Runs `i18next-parser` over `src/**/*.{js,jsx}` (configured in [`package.json`](../package.json)) and copies English to `src/locales/en/`. Review generated keys in `public/locales/` before committing.

## Locale support

Four UI locales: English, French, German, and Italian. Users change language via the footer dropdown. Relative timestamps (`javascript-time-ago`) follow the active locale via [`TimeAgoLocaleSync`](../src/components/TimeAgoLocaleSync.js).

## UI language vs communication language

These are independent:

| Setting | Where | Stored | Used for |
|---------|-------|--------|----------|
| **UI language** | Footer [`LanguagePicker`](../src/components/LanguagePicker.js) | Browser `localStorage` (`i18nextLng`) | Website strings (`apfront` namespace) |
| **Communication language** | User settings → [`UserSettingsModal`](../src/components/UserSettingsModal.js) | `user.language` on backend (`new_setting`) | Emails and push notifications (`apback` on node-backend) |

Changing communication language does not call `i18n.changeLanguage` or alter footer/localStorage UI preferences.
